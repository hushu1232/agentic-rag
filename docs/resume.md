# 简历叙事 · 这个项目怎么讲

> 给谁看：一个会在面试里追问「你这个混合检索到底有没有用」的人。
> 原则：**每个数字都能指回一个文件、一条命令**。指不回去的数字不要写。

## 1. 为什么这个项目适合写简历

绝大多数「RAG 项目」在简历上的问题是同一个：**只有搭建，没有测量**。「基于 LangChain 实现了 RAG 检索问答」——面试官无法判断它比十个同类项目好在哪。

这个项目的差异点在**评测层和缺陷清单**，不在检索层：

| 常见的 RAG 项目 | 本项目 |
|---|---|
| 跑通了，能回答 | 30 条三类样本，5 个指标，阈值门禁，不达标 `exit 1` |
| 「用了混合检索，效果更好」 | 4 组消融实验，每一步的增量以百分点写进 diff 表 |
| 「参考了开源实现」 | 读完 13 个源文件，定位 15 个可复现缺陷（其中 1 个让核心功能静默失效），逐条写了回归测试 |
| 无法判断是否在编 | 6 条「语料里没有答案」的题，专门考拒答；拒答可被规则判定 |

**一句话定位**：不是「我做过 RAG」，是「我知道一个 RAG 系统哪里会坏、怎么证明它没坏」。

## 2. 简历里的写法

### 三行版（项目栏，字数受限时用）

> **Agentic RAG 问答服务**（Python / LangGraph · 个人项目）
> · 手写状态图实现路由—拆解—多跳检索—规划熔断五节点，混合召回（向量 + BM25）用 RRF 融合，零中间件可离线跑通
> · 建 30 条评测集（单跳 / 多跳 / 无答案三类）+ 5 指标 + 阈值门禁，4 组消融实验量化各模块增益
> · 审计公开实现定位 15 个缺陷（含 1 处条件边读错字段导致多跳循环失效），逐条补回归测试

### 六行版（附件简历 / 作品集）

> · **问题**：单路向量召回对字面量（`4,409` 题、`IsUse` 反思 token、`HotpotQA`）几乎不可分，且无法判断该不该检索、该不该停下。
> · **方案**：LangGraph 手写状态图，`route` 判要不要检索（simple 直答不检索）、`decompose` 拆 1–6 条有序子问题、`plan` 决定继续或生成并在代码层加两道硬熔断、`answer` 只依据 selected 片段作答。
> · **检索**：向量（numpy 精确余弦，索引存 npz）+ BM25（英文词级，保留数字与 `recall@k` 词形）双路并行，RRF 按名次融合，规避两路分数量纲不可比；rerank 留接口默认关闭。
> · **评测**：语料取 14 篇 RAG 方向顶会论文（NeurIPS/ICLR/ACL/EMNLP/NAACL/TACL，83 万字，切块 1,357 个片段；全文不入库，用 `corpus.lock.json` 锁版本与 sha256 复现），30 条标注集事实全部可从原文逐字定位；`context_recall` 确定性、`groundedness`/`answer_relevance` 走结构化判官、`refusal_accuracy` 走固定标记规则判定 + 判官复核，另加 `routing_accuracy`；6 条无答案题附 `absence_proof`（grep 0 命中），判官失败记 `null` 并单设 `null_rate` 闸。
> · **结果**：门禁 6 项（含 `null_rate` 反向闸）；四组消融为「单路向量 → +BM25 拼接 → +RRF → +多跳」，其中「+BM25 拼接」一档复刻了源实现的形态，用来把「有没有融合」和「有没有关键词路」拆成两个问题。**具体百分点等真实 embedding key 到位后填入**——当前索引用的是确定性哈希占位向量，只能验证链路，指标不可引用。
> · **工程量**：核心代码 750 行（物理 1187，含注释）/ 6 个直接依赖 / 37 个离线回归断言（假模型注入，约 4 秒，不耗 token、不联网）。

## 3. 三个必被追问的问题，和答法

**Q1「为什么叫 Agentic？这不就是个 if-else 流程？」**
> 图是固定的，但**决策点是模型给的**：要不要检索由 `route` 结构化输出决定；拆几条、按什么顺序由 `decompose` 决定；检索够了没有由 `plan` 决定。代码只保留两道硬熔断兜底，不替模型做选择。我特意没做 replan（重拆子问题），因为它让熔断失去参照物——这个取舍写在了 decisions.md 里。

**Q2「混合检索真的有用？还是自我感觉良好？」**
> 有消融表，而且第二档特意做成「拼接」而不是「加权」：单路向量 → 双路拼接去重 → RRF → 加多跳。第二档就是源实现的形态（两路结果直接拼、按 id 去重，向量相似度完全不参与排序），所以「+RRF」那一行涨的百分点，正好回答「融合到底值不值」。不按分数加权是因为两路量纲不可比——余弦 0–1，BM25 无上界还随语料规模漂移，任何系数都是拍脑袋。四条命令能复现，报告在 `reports/ablation-*.md`。

**Q3「为什么不用 Milvus / Elasticsearch？是不是不会？」**
> 会，但在这个量级是负收益。1,357 个片段下 numpy 精确余弦是毫秒级且**逐位可复现**，ANN 只带来近似误差；ES 的 analyzer 要维护同义词与词干，而关键词侧我只需要它对字面量无损——`4,409`、`IsUse`、`HotpotQA` 这些词形小写切词后就是原样 token，够用。真正的理由是评测：离线、零中间件、`pip install` 之后一条命令跑通，才能让 `--baseline` 的 diff 有意义。规模到十万级后我写了扩展点（换 ANN、分批 embedding），但没验证过，这一点我写在已知限制里。

**Q4「语料是你选的、题是你出的、答案也是你定的，这不算自证？」**
> 题和答案是我写的，但**事实不是我编的**：每一题的参考答案都能在论文原文里逐字定位，数字直接用 grep 取，标注的片段 id 指向原文那一段。无答案的题更硬——`absence_proof` 里存了当时的 grep 命令和 0 命中结果，当场可以重跑。真正由我决定的只有「问什么」，而「问什么」恰好是最不需要信誉的部分：换一个人来问，语料里的答案不会变。这套东西真正的软肋是判官，所以我把它拆成两个数字：`groundedness` 衡量能力，`null_rate` 衡量判官可靠性，后者超标直接 fail。

**Q5「你审出别人 15 个缺陷，那你自己写的有没有？」**
> 有，而且是被自己的测试抓出来的。`answer` 节点用「召回为空」当拒答条件，但 `route` 判 `simple` 时**本来就不检索**，候选恒为空——于是「15% of 200 等于多少」这种题会被答成「无法从资料确认」。写测试之前它跑得很优雅，看起来像个谨慎的系统。`test_simple_has_no_selected_but_still_answers` 一跑就红了，修法是拒答条件里加 `strategy != "simple"`，记在 ADR-017。同一轮还有一处：`D08` 的测试最初只测了 `rrf_fuse` 这个纯函数，我把 `search` 里的融合换成拼接，测试照样绿——补了一条走 `Retriever.search` 的断言才算真的钉住。

## 4. 数字的唯一来源

| 简历上的数字 | 从哪来 | 怎么复现 |
|---|---|---|
| 5 个指标数值 | `reports/{ts}-eval.json` | `python -m evals.run --gate` |
| 消融增量 | `reports/{ts}-ablation.md` | `python -m evals.run --ablation` |
| 核心行数 750（代码）/ 1187（物理） | 两个数分开报，口径见 ADR-016 | `wc -l app/*.py` 得物理行；代码行用 `tokenize` 排除注释与空行 |
| 缺陷 15 个 | `docs/source-audit.md` 表格 | 直接看文档 |
| 语料规模 | `wc -m data/corpus/*.txt`、`wc -l .index/chunks.jsonl`、`data/corpus.lock.json` | 先 `python scripts/fetch_corpus.py` |

**没有跑出来的数字，一律留空并写「未完成」**。留空被发现只是没做完，编数字被发现是诚信问题。

## 5. 不要写进简历的三类话

1. **「痛点是 X，因此 Y」式排比**——面试官看不到你的判断，只看到模板。
2. **未经测量的形容词**（高效、显著提升、大幅优化）——一律换成百分点或毫秒数。
3. **抄来的架构名词**（多智能体、AutoGen、CrewAI）——这个项目刻意只用 StateGraph，手写五个节点，就是为了能逐行解释。套娃框架会让人无法追问到你的思考。
